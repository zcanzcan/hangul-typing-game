# 11. 단계별 개발 지시서

AI 코딩 도구(Codex, Claude Code 등)가 이 문서를 보고 **한 번에 한 단계씩** 개발한다.
단계 순서와 범위는 [08. 기술 구성과 개발 순서](08-tech-and-roadmap.md)를 따르고, 각 단계에서 읽을 문서와 완료 기준을 여기에 정리했다.

## 사람이 AI에게 하는 말

매번 아래 한 줄이면 된다. `N`만 바꾼다.

```
docs/11-dev-steps.md를 읽고 N단계를 개발해 줘.
```

다음 단계가 몇 단계인지 모르겠으면 이렇게 말한다.

```
docs/11-dev-steps.md를 읽고 아직 안 끝난 다음 단계를 개발해 줘.
```

## 진행 상황

AI는 단계를 끝낼 때 같은 PR에서 해당 줄을 `[x]`로 바꾼다.

- [x] 0단계. 프로젝트 준비
- [x] 1단계. 타자 엔진
- [x] 2단계. MVP 화면
- [ ] 3단계. 유행어 모드
- [ ] 4단계. 태블릿 다듬기와 PWA
- [ ] 5단계. P1 기능
- [ ] 6단계. P2 기능

## 모든 단계 공통 규칙 (AI가 지킬 것)

1. **시작 전에 읽는다:** [`CLAUDE.md`](../CLAUDE.md)(개발 규칙, 도구 이름과 상관없이 모두 지킨다), 이 문서, 해당 단계의 "읽을 문서".
2. **요청한 단계만 한다.** 다음 단계 기능을 미리 만들지 않는다. 이전 단계가 `[ ]`이면 먼저 알린다.
3. **문서가 정답이다.** 타입 이름과 필드는 [05. 데이터 구조](05-data-model.md), 점수 공식은 [04. 타자 판정과 점수 규칙](04-typing-and-scoring.md)을 그대로 쓴다. 문서와 다르게 해야 할 이유가 생기면 바꾸지 말고 먼저 물어본다.
4. **새 브랜치에서 작업하고 PR로 올린다.** 브랜치 이름은 `step-N-짧은설명` (예: `step-1-typing-engine`).
5. **올리기 전에 확인한다:** `npm run lint`, `npm test`, `npm run build`가 모두 통과해야 한다 (0단계부터).
6. **PR 설명에 적는다:**
   - 만든 것 목록
   - lint, test, build 결과
   - 문서가 애매해서 스스로 정한 부분
   - 사람이 직접 확인해야 할 것 (실기기 테스트 등)
7. **이 문서의 진행 상황 체크박스**를 같은 PR에서 `[x]`로 바꾼다.

## 0단계. 프로젝트 준비

**목표:** 코드를 올릴 뼈대와 자동 배포를 만든다. 화면은 아직 만들지 않는다.

**읽을 문서:** [08](08-tech-and-roadmap.md) (추천 기술 스택, 폴더 구조)

**할 일**
- 저장소 루트에 Vite + React + TypeScript 프로젝트를 만든다. 기존 `docs/`, `data/`, `README.md`, `CLAUDE.md`, `LICENSE`는 그대로 둔다.
- ESLint, Prettier, Vitest를 설정하고 `npm run lint`, `npm test`, `npm run build` 스크립트를 만든다.
- 08의 폴더 구조대로 `src/` 아래 빈 폴더(또는 `index.ts`)를 만든다.
- GitHub Actions: PR마다 lint·test·build를 돌리고, `main`에 올라가면 GitHub Pages로 배포한다.
- 첫 화면은 "한글 타자 게임 준비 중" 한 줄이면 된다.

**완료 기준**
- [ ] `npm run lint`, `npm test`, `npm run build` 통과
- [ ] PR에서 GitHub Actions 검사가 돈다
- [ ] 사람이 할 일(저장소 설정에서 Pages 켜기 등)이 있으면 PR 설명에 적었다

## 1단계. 타자 엔진

**목표:** 화면 없이 한글 입력 판정과 점수 계산 로직을 테스트와 함께 완성한다.

**읽을 문서:** [04](04-typing-and-scoring.md) (전부), [05](05-data-model.md) (기록 타입)

**할 일** (`src/typing/`)
- `judge.ts`: 제시어와 입력값을 비교해 글자별 맞음/틀림/조합 중을 돌려준다. 조합 중인 마지막 글자는 "앞부분이 맞는지"만 본다 (제시어 `강`, 입력 `가` → 아직 틀림 아님). `keydown`이나 `keyCode`에 의존하지 않는다.
- `metrics.ts`: 자모 기준 타수(1분 환산), 정확도(`맞게 입력한 글자 수 ÷ 제시된 글자 수 × 100`), 점수(`타수 × (정확도/100)² × 단계 보너스`), 단계 통과 여부(연령대별 기준). 어르신 "시간 제한 없음" 모드는 타수 대신 정확도와 완료 개수만 돌려준다.
- `layout.ts`: 두벌식 자판 배치. 글자를 눌러야 할 키 목록으로 바꾼다 (쌍자음은 Shift + 자음).
- 앱 화면 키보드로 누른 자모를 글자로 조합하는 함수(IME가 없을 때 쓰는 오토마타)도 만든다.
- 판정 입력은 입력칸의 현재 값과 조합 중 여부뿐이다. 화면은 `input`, `compositionstart`/`compositionend` 이벤트에서 이 값을 넘긴다 (태블릿 대응).
- 한글 분해·조합은 `es-hangul`을 쓴다.

**완료 기준 (단위 테스트로 증명)**
- [ ] `사과` = 5타, 30초에 50타 → 타수 100
- [ ] 쌍자음(ㄲ ㄸ ㅃ ㅆ ㅉ)은 Shift 포함 1타
- [ ] 겹받침(ㄳ, ㄺ 등)과 겹모음(ㅘ, ㅢ 등)의 자모 수가 맞다
- [ ] 조합 중인 글자는 틀림으로 세지 않는다
- [ ] 점수 공식과 단계 보너스(1.0 / 1.2 / 1.5 / 1.8)가 04와 같다
- [ ] 연령대별 단계 통과 기준(초등 85%, 성인 90% + 타수, 어르신 80%)이 04와 같다
- [ ] 시간 제한 없음 모드는 타수 없이 정확도와 완료 개수만 나온다
- [ ] `layout.ts`가 `강` → ㄱ(r) ㅏ(k) ㅇ(d) 같은 키 목록을 돌려준다
- [ ] 화면 키보드 조합: ㄱ, ㅏ, ㅇ을 차례로 누르면 `강`이 된다

## 2단계. MVP 화면

**목표:** 유행어 모드를 뺀 첫 버전 화면을 만든다.

**읽을 문서:** [02](02-features.md) (P0 기능), [03](03-screens-and-flow.md) (화면과 흐름), [07](07-design.md) (색, 글꼴, 접근성), [05](05-data-model.md), [01](01-overview.md) (연령대 프리셋)

**할 일**
- 시작 화면(연령대 선택, 닉네임) → 메인 메뉴. 로그인 없음, 개인정보 수집 없음.
- 자리 연습, 낱말 연습(입력 후 뜻 카드), 짧은 문장 연습. 자리 → 낱말 → 문장 단계식 진행.
- 화면 키보드(다음 키 빛남, 태블릿에서 직접 눌러 입력 가능).
- 결과 화면(타수, 정확도, 점수, 틀린 낱말), 내 기록(모드별 최고·최근 기록), 틀린 낱말 다시 연습.
- 최고 기록은 닉네임 × 모드 × 단계별로 저장한다. 갱신하면 축하 효과(색종이, 캐릭터 칭찬, 스티커 1개)와 "이전 최고 기록 대비 +12점" 같은 차이를 보여준다.
- 시간 제한 없음 모드 기록은 순위 비교에서 따로 분리한다.
- 설정: 글자 크기 3단계, 효과음 켜기/끄기, 연령대 변경, 기록 초기화(한 번 더 확인).
- 기록은 localStorage/IndexedDB에만 저장한다.
- 낱말·문장 데이터는 `public/data/`에 두고, 처음에는 `data/samples/`를 옮겨 쓴다. 예문은 직접 쓴 문장만 쓴다.
- 디자인은 07의 캔디 테마 CSS 변수를 쓴다. 글자 대비 4.5:1, 버튼 48×48px 이상.

**완료 기준**
- [ ] 08 "첫 버전 완료 기준" 중 유행어를 뺀 항목이 PC 크롬에서 된다
- [ ] 새로고침해도 기록이 남는다
- [ ] 연령대 프리셋이 글씨 크기와 시간 제한에 반영된다
- [ ] 화면별 기본 동작 Playwright 테스트가 1개 이상 있다

## 3단계. 유행어 모드

**목표:** 설정에서 켜는 유행어 카드게임을 만든다.

**읽을 문서:** [02](02-features.md) (S-1 ~ S-4), [04](04-typing-and-scoring.md) (카드게임 점수), [05](05-data-model.md) (유행어 타입), [06](06-slang-operations.md), [07](07-design.md) (픽셀 테마)

**할 일**
- 설정에서 유행어 모드 켜기/끄기 (기본 꺼짐).
- `public/data/slang.json` 불러오기. 기본 목록에는 `kidSafe` 검수를 거친 항목만 넣는다.
- 뜻 맞히기 카드게임: 4지선다, 맞히면 유행어를 한 번 입력. 한 판 10문제.
- 점수(04): 정답 +100, 오답 0, 정답 후 유행어 입력이 정확하면 +50, 3연속 정답부터 문제당 +20 콤보.
- 설정에서 유행어 직접 추가 (기기에 저장). 금칙어 필터(`blocklist.json`)를 통과해야 저장된다.
- 유행어 모드와 점수판은 픽셀 테마(07)로 보여준다.

**완료 기준**
- [ ] 유행어 모드를 켜면 카드게임이 되고, 설정에서 추가한 유행어가 문제로 나온다
- [ ] 금칙어가 들어간 유행어는 추가되지 않는다
- [ ] 카드게임 점수(+100, +50, 3연속부터 +20)에 단위 테스트가 있다

## 4단계. 태블릿 다듬기와 PWA

**목표:** 태블릿에서 한글 입력이 제대로 되고, 홈 화면에 설치할 수 있게 한다.

**읽을 문서:** [04](04-typing-and-scoring.md) (태블릿 입력 처리), [03](03-screens-and-flow.md), [08](08-tech-and-roadmap.md)

**할 일**
- 화면 키보드가 가려지거나 입력칸이 밀리는 문제를 고친다 (가상 키보드가 올라올 때 레이아웃).
- `vite-plugin-pwa`로 설치와 오프라인 캐시를 넣는다.
- 실기기 테스트 체크리스트를 PR 설명에 적는다 (AI가 직접 못 하는 부분은 사람이 확인).

**완료 기준**
- [ ] iPad 사파리, 안드로이드 태블릿 크롬에서 한글 입력 판정이 맞다 (사람 확인)
- [ ] 홈 화면에 추가되고 인터넷 없이 연습이 된다

## 5단계. P1 기능

**목표:** 두 번째 버전 기능을 넣는다. 기능이 많으므로 **기능 하나당 PR 하나**로 나눈다.

**읽을 문서:** [02](02-features.md)의 P1 항목, 관련 문서 (04 미니게임 점수, 06 유행어 운영 등)

**할 일** (순서 추천)
1. 받침·쌍자음 단계 (T-6)
2. 떨어지는 낱말 막기 미니게임 (T-8). 점수와 속도는 04대로 (글자 수 × 10점, 바닥에 3개 닿으면 끝, 30초마다 10% 빨라짐)
3. 가족 점수판 (R-4)
4. 소리 읽어주기 (A-5). 한국어 목소리가 없는 기기에서는 버튼을 숨긴다.
5. 오늘의 낱말 (M-4), 그림 카드 (M-2, 이모지나 직접 만든 그림만)
6. 헷갈리는 맞춤법 (M-5), 긴 문장 연습 (T-4), 속도 조절 (A-4)
7. 유행어 등록 날짜와 출처 (S-5), 옛 유행어 보관 (S-6), 원격 업데이트 (S-7)

**완료 기준**
- [ ] 위 목록이 모두 `main`에 들어갔다
- [ ] 점수 규칙이 있는 기능(미니게임 등)은 단위 테스트가 있다

## 6단계. P2 기능

**할 일**

- 틀린 맞춤법 고치기 (M-6), 속담·사자성어 퀴즈 (M-7), 하루 10분 도장 (A-8).

**완료 기준**
- [ ] 반 점수판이 닉네임과 점수 외의 정보를 서버로 보내지 않는다
- [ ] 나머지 P2 기능이 `main`에 들어갔다
